# UI language (locale)

Target: French by default, English available, with browser-language
auto-detection for components that support it — `platform.yaml`'s
`locale` section (`default: "fr"`, `available: ["fr", "en"]`) is the
single source of truth.

This is **not** a numbered study requirement (`office365-exit-study.md`
never asks for a specific UI language) — added on request. What follows is
an honest, per-component breakdown of what's actually wired versus what
still needs verification: several components could not be confirmed
against a real config mechanism from the sandboxed environment this was
built in (no live instance to inspect, and vendor documentation wasn't
conclusive for all of them) — flagged individually below rather than
guessed.

| Component | Status | Notes |
|---|---|---|
| **Keycloak** | ✅ Wired | `infra/ansible/roles/keycloak_realm/tasks/main.yml` sets the realm's `internationalization_enabled`/`supported_locales`/`default_locale` from `platform.yaml`'s `locale` section. Keycloak's login/account UI then respects the browser's `Accept-Language` automatically when internationalization is enabled, falling back to `default_locale`. **Caveat**: the exact snake_case parameter names of the `community.general.keycloak_realm` Ansible module were inferred from Keycloak's own long-stable REST API field names (`internationalizationEnabled`/`supportedLocales`/`defaultLocale`) and this module's own already-established snake_case↔camelCase convention (e.g. `display_name`↔`displayName`, used elsewhere in the same file) — not directly verified against the module's source, since `community.general` isn't installed offline in this sandbox (see the repo's CI job, which does install it, for where this could be confirmed). |
| **Element Web** | ✅ Nothing to do | Confirmed via Element Web's own `docs/config.md`: there is **no** `default_language` config key. It auto-detects the browser's language on its own by default; the only documented language-related settings are `disable_login_language_selector` (hide the switcher) and `custom_translations_url` (override strings) — neither needed here. |
| **Vikunja** | ⚠️ Likely auto-detects, not directly confirmed | Vikunja ships its own Crowdin-based translation pipeline (`crowdin.yml` at the repo root) and a Vue.js frontend, the common pattern for which is browser-language auto-detection with no server config. Could not locate and confirm an explicit `config.yml` locale key from this sandbox (the expected sample-config path 404'd). Verify directly against a running instance before assuming no action is needed. |
| **Seafile** | ⚠️ Not confirmed | Seafile's `seahub_settings.py` (already templated by `infra/ansible/playbooks/seafile.yml`, the natural place to add a locale setting) is widely reported in community documentation to support a `LANGUAGE_CODE` Django setting, consistent with Seafile/Seahub being a Django application — but this could not be confirmed against an authoritative source from this sandbox (only a wiki page pointing to `manual.seafile.com`, itself not reachable here). Verify `LANGUAGE_CODE` against `manual.seafile.com` or a running instance, then add it to `infra/ansible/templates/seahub_settings.py.j2` following the same domain-driven pattern already used there. |
| **PeerTube** | ⚠️ Not confirmed | PeerTube's `config/production.yaml.example` almost certainly has an `instance:` section with language-related keys, but the fetched excerpt from this sandbox was truncated before reaching it. Needs a follow-up look at the full file (or a running instance's admin settings) before wiring anything. |
| **OnlyOffice, Grommunio-web, Novu, Gokapi, SeaweedFS, PeerTube (video player UI)** | ❌ Not investigated | Out of the research budget available in this pass. OnlyOffice's document editor already auto-detects the browser's language for its own UI in practice (community reports), but this wasn't independently confirmed here. Grommunio-web likely has a per-user language setting in its own web UI (common webmail pattern) rather than a global admin default — worth checking `grommunio/grommunio-documentation`'s `web/` docs directory directly. Novu, Gokapi and SeaweedFS's admin console are not known to have meaningful multi-language UIs; treat as English-only unless proven otherwise. |

## Why this isn't one script-generated setting like domains/versions

`platform.yaml`'s `domains` and `services[*].version` are propagated by
`scripts/sync_platform.py` because every consumer file uses the exact same
literal (a hostname, a tag) that a text substitution can find and replace
mechanically. Locale is different: each component that supports it has its
own config *shape* (a realm attribute here, a Django setting there, a
YAML key elsewhere) requiring per-component code, not a generic pattern —
so each row above is wired by hand, in whichever file already owns that
component's configuration (an existing Ansible role/template where one
exists, a new one otherwise), reading `platform.yaml`'s `locale` values
rather than hardcoding `"fr"`/`"en"` again.
